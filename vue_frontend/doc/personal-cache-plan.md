# 个人页面缓存现状与优化计划

## 结论与定位

多用户并未让所有缓存失效，但引入个人投影后，缓存必须有账号归属，不能再只用AVID/查询条件区分。当前请求频率增加的直接原因是个人中心以section为key重新挂载面板，观看列表无条件在focus/visibilitychange刷新，设置面板每次挂载查询来源能力；不是数据库JSON设置导致。settings store已有loaded/在途去重及sessionEpoch，App按登录身份重置它，正常切换页面不应重复GET设置。

资源列表resourceList、演员/类别directoryStore持有当前结果，但load/fetchResources每次调用均请求，没有多查询TTL缓存。API客户端默认no-cache/no-store请求头，不等于应用内存不能缓存；个人接口的private,no-store仍必须保留，禁止改为公共HTTP缓存。资源详情ETag绑定用户/个人状态，可以安全做条件验证；当前通用客户端尚未支持将304与已保存envelope合并。

推荐页已有按owner保存的视图恢复与组件局部黑名单缓存。外部搜索ExternalSearchPanel的sessionStorage key目前仅有实体类型/ID/来源，没有账号维度，而且保存了job句柄（任务ID及令牌）；登出时App仅清理推荐恢复/播放草稿，没有统一清理external_cn_v4项。这是多用户需要补齐的隔离边界：后台鉴权仍须拒绝跨账号任务，但前端不应恢复旧账号句柄或个人投影。封面object URL以AVID为key，也尚无统一登出清理和在途发布fence。其中共享搜索内容是原站事实，收藏、已观看、黑名单与添加状态必须重新投影。任务/播放会话快照是实时控制状态，不能套用普通页面TTL而停掉版本轮询。

## 本轮已实现

- 个人中心最多保留四个已访问面板，切换保留页码与未保存设置预览；退出中心释放组件，不长期保留DOM。停用的观看面板停止展示查询与弹窗，旧请求不得修改它，监听卸载时解除。
- viewing store缓存历史/稍后再看查询30秒、最多8项，key为kind/page/page_size；App身份变化清空内存并提升revision，在途请求旧epoch不可回填。相同查询去重，手动刷新/重试强制绕过缓存；失败不缓存，容量有界。刷新后只保留仍在该页且观看时间未变的选择。
- 当前页面个人状态更新、资源删除、真实playing上报、列表删除成功以无载荷事件使观看缓存失效；可见面板补读，隐藏面板下次激活补读。其他标签/设备更新在再次聚焦时检查TTL，缓存新鲜期为30秒，超过后在聚焦/切换时补读，可手动立即刷新；持续停留页面不周期轮询。本轮未实现跨标签推送。
- KeepAlive避免通用设置来源能力重复挂载请求，继续使用settings store的登录归属/保存分区；切换不会把另一分区草稿保存。减少动态偏好时禁用面板过渡。
- 不将备注、个人列表、Cookie或播放会话写入localStorage；不会将失败、部分结果或控制终态当作可长期缓存的完整查询。

## 后续执行顺序

1. 优先修复外部搜索恢复：区分共享原站事实与个人job句柄，个人部分使用账号+登录epoch并登出清理；恢复后重新核查任务权限、资源存在/黑名单投影，禁止复用旧账号令牌。封面blob补登出回收与旧请求发布fence；即使共享图片允许复用，也不能保留旧认证请求上下文。
2. 建立按登录epoch、规范化参数、领域revision分区的有界查询缓存，先接资源列表与目录（建议30–60秒、每领域20项）。合并在途查询，保留旧内容刷新；对身份变化、失败与乱序做调用次数测试。不要只用username跨重新登录复用个人值。
3. 将元数据/封面事实与个人投影分开：共享事实按资源版本复用，个人状态按账号版本合并。封面object URL缓存补在途去重、版本失效及撤销；未认证的旧请求不能在登出后重新发布旧blob。
4. 以细粒度领域事件统一写后失效；使用BroadcastChannel仅广播无私密数据的失效信号，身份与revision仍在当前实例校验。跨设备优先短TTL聚焦补读，再评估服务端版本通知，避免全站高频轮询。
5. 为个人详情/设置提供完整ETag条件请求能力，客户端只在已有同账号快照时处理304；设置加载须区分服务器基线与未保存草稿，后台刷新不得覆盖正在编辑的字段。先测请求量/传输量再调整TTL。
6. 推荐黑名单和恢复记录统一账号key/容量/TTL/写后失效；外部搜索继续手动启动，缓存命中重新应用个人过滤。任务job_id/version、播放session/generation/lease与取消协议保持实时，不进入以上通用页面缓存。

每阶段检查登录切换、同账号重登录、标签页恢复、跨页写后读、失败重试、旧响应与缓存上限；浏览器记录切换前后GET次数，区分隔离验证与正式环境。缓存优化不削弱服务器鉴权或恢复旧用户数据。
