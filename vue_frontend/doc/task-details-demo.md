# 任务详情 Demo

设计问题：下载与新增/刷新刮削共用入口时，哪种布局便于查看状态、定位失败和阅读明细？本轮使用三种结构供比较，尚未选定正式布局。

从前端目录运行：

```bash
pnpm demo:tasks
```

在现有 `/downloads` 页面使用开发预览参数，保留应用导航与登录流程：

- `/downloads?demo=tasks&variant=list`：A，任务列表与右侧明细，便于逐项检查。
- `/downloads?demo=tasks&variant=board`：B，按状态分组看板，便于观察队列分布。
- `/downloads?demo=tasks&variant=timeline`：C，活动时间线与明细，便于查看阶段先后。

底部按钮或左右方向键切换布局，URL 保留选项；表单与弹窗内不拦截方向键。支持全部/下载/刮削筛选、任务状态、选中明细与内存中的阶段演示；所有任务数据均为模拟，不提交、取消或重试真实任务，不保存演示状态。下载显示百分比、速度和大小；刮削显示实际阶段名称，不伪造下载进度。

Demo 组件仅在开发环境加载，生产构建不包含此页面和切换器。正式下载入口及名称保持既有行为；开发 Demo 中页面与导航名称为“任务详情”。选定布局后再实现正式入口、旧 URL 兼容与真实状态适配，不将模拟结果当作真实任务。

真实接入需复用 downloadQueue 和现有 visibleScrapeJobs，统一展示层状态而保留两种任务的阶段差异。当前刮削列表来自本浏览器追踪的任务，不代表服务器完整历史；翻译已排队不代表翻译完成。正式历史、跨设备可见性和可取消范围需在接入阶段明确。
