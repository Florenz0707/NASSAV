# 中性色卡片 UX 执行记录

本轮保持页面布局与业务协议，按“中性色卡片”方案统一交互与页面反馈。比例为视觉层级指引，资源封面不强制改色。

## 第一阶段：公共控件

分支：`feat/ux-neutral-controls`。提交可由同名分支或 Git 日志定位。

- 主题增加中性辅助表面、悬浮/按下、危险浅底、禁用和焦点 token；重点色上文字继续使用固定浅色。
- AppButton 五态保持尺寸；AppInput 提供清空、焦点、关联错误；添加资源和登录接入。
- 加载图标改为单层 1.5 秒旋转，尊重减少动态效果偏好。
- 验证：`pnpm run check`、`pre-commit run -a`、`pnpm run test:browser`。浏览器使用模拟 API；不代表真实服务联调。
- 新增 `uxControls.cjs`：深浅主题三类按钮的默认/悬浮/按下态文字对比度、加载尺寸、输入清空与错误关联、减少动态效果。

## 第二阶段：页面反馈

第一阶段提交：`4986eb0`。第二阶段分支：`feat/ux-page-feedback`。

- 公共 PageLoad 超过一秒显示骨架或单层 loading；资源、目录、推荐与外部搜索使用内容骨架，详情使用封面/信息骨架。
- 资源和目录失败显示重试，不再误报空列表；刷新保留内容，外部搜索保留部分结果及手动触发/取消协议。
- 设置加载失败显式提示；保存防止重复提交。任务读取失败可重试，持久控制协议不变。
- 详情元数据加入请求归属检查，路由切换与卸载使旧响应失效。
- 验证：`pnpm run check`、`pre-commit run -a`、`pnpm run test:browser`；新增 `uxPages.cjs` 验证延迟、稳定骨架、失败/空状态区别、重试与刷新保留内容。均为隔离或模拟验收。

## 第三阶段：页面视觉收敛

第二阶段提交：`52ebe35`。第三阶段分支：`feat/ux-neutral-page-polish`。

- 应用外壳、首页和推荐区的大面积背景改为中性色，分页与次要操作收敛为 neutral，确认删除统一 danger。
- 资源卡片/详情保留原布局和按钮尺寸，移除覆盖公共状态的背景；提交下载和添加推荐资源使用稳定 loading 占位。
- Cookie 编辑接入 AppInput，保存防止重复提交、失败就地说明；Cookie 列表使用延迟 loading 与可重试错误。
- 强调色前景与按钮底色分离，降低深色模式视觉重量而保持小字清晰；合并主题旧值，公共链接辅助样式补齐交互状态。
- 推荐页窄屏标题与操作分行，按钮两列排列；浏览器断言保证文案不竖排。主内容保留路由焦点而不绘制整页描边，控件保留各自焦点反馈。
- 验证：`pnpm run check`、`pre-commit run -a`、完整 `pnpm run test:browser`。浏览器深浅主题/移动端截图及模拟场景通过后合并；真实部署体验仍需用户验收。

## 暖色视觉调整

分支：`feat/ux-warm-accents`，前一阶段提交：`b38684b`。

- 按用户反馈恢复暖橙渐变背景，深浅主题表面、辅助色与边框改为暖中性色。
- 资源库刷新和添加页 Cookie 按钮使用 AppButton warm tone，保留交互状态、禁用与加载契约。
- 下载源移除外层原生控件样式，保留 CustomSelect 内部单层边框、标签和键盘行为。
- 验证：`pnpm run check`、`pre-commit run -a`，以及相关 Playwright 深浅主题、按钮状态、Cookie 弹窗、语义和移动端检查；模拟 API 与真实部署验收分开。
