# 重构原则与持续开发约束

本文将本轮后端能力重构和前端 F1–F6 的做法作为后续开发基线。具体职责分别由[后端任务架构与职责](../django_backend/doc/task-control-architecture.md)和[前端开发契约](../vue_frontend/doc/development-contracts.md)维护；Agent 入口为[仓库规范](../AGENTS.md)。本文约束新增与修改代码，不要求为无关旧代码补建继承层。

## 设计原则及落地方式

| 原则                   | 本轮落地                                                                                       | 后续约束                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 面向接口编程、依赖倒置 | 后端 workflow 消费小能力契约，composition 装配生产 Adapter；前端目录工厂接收 API 能力          | 使用公开消费者契约；核心不得自行构造生产依赖或访问实现私有状态                           |
| 单一职责               | 后端分离 HTTP/Celery、用例、ORM/文件/Redis；前端分离页面装配、列表、下载队列、连接及推荐黑名单 | 按变化原因和状态所有者划分职责；传输模块不接管页面展示与领域状态                         |
| 开闭原则               | 来源、列表策略、推荐因子通过实现、注册与 hook 扩展；演员/类别通过公共视图适配                  | 新实现接入已有扩展点；避免在通用流程中不断增加来源名或实体名分支                         |
| 接口隔离、可替换性     | 契约按消费者能力拆分，测试替身和生产 Adapter 使用同一接口                                      | 不为所有模块强制增加 ABC；纯函数、数据对象和简单框架入口保持简单，接口变更同步全部消费者 |
| 合理复用               | 公共按钮、弹窗、查询护栏、标题选择及目录/详情逻辑统一                                          | 复用相同语义和生命周期，允许头像、徽标等展示差异；不按文件行数机械拆分                   |
| 行为兼容、显式失败     | 冻结 URL/任务名等契约；保护锁 owner、翻译收尾和异步结果归属                                    | 结构调整保留行为；语义修复单独说明新旧行为，覆盖失败、取消、部分成功和终态               |

开闭原则允许为真实的新需求修改契约和装配，但必须说明影响并同步消费者。它不意味着禁止修改已有文件，也不意味着为假想扩展构建插件框架。

## 变更时必须明确的边界

开始前指出状态的所有者、依赖方向和公开入口。后端能力方法同时约束输入、输出、异常及副作用顺序；前端组件契约同时约束 props、事件、交互状态和卸载清理。有共享语义时先检查既有实现，再决定是否增加抽象。

HTTP 字段、URL、Celery task 名称和队列、Redis key/TTL、缓存 key、文件路径、metadata、关系规则及前端标题回退属于消费者行为。仅移动职责不得顺便改变这些行为；确需修改时更新接口/数据说明和对应回归，不能为了让测试通过自动重建契约快照。

异步工作必须定义加载、错误、取消、部分结果和终态。取消当前请求或订阅不等于取消后台任务；旧响应、旧任务事件和失租执行不得写入新状态或发布成功副作用。异常收尾只处理本次执行仍拥有的状态，不覆盖其他执行或已完成结果。

## 质量门槛

仓库根目录始终执行 `pre-commit run -a`，保留命令退出码。按改动选择行为检查：

```bash
# 后端离线门槛；从仓库根目录运行
cd django_backend
uv run pytest tests/ --ds=django_project.refactoring_test_settings -v
```

```bash
# 前端 lint、单元测试与构建；从仓库根目录运行
cd vue_frontend
pnpm run check
```

后端默认 pytest 配置使用实例设置，隔离门槛必须明确传入 `--ds`；依赖和在线测试规则见[测试说明](../django_backend/tests/README.md)。前端主题、布局、键盘、焦点或弹窗生命周期改动须补充浏览器检查，已有模拟套件入口见[前端 README](../vue_frontend/README.md#公共组件浏览器验收)。选择能检查实际契约的回归，不以纯实现细节测试代替消费者行为。

失败先定位并修复再重复对应门槛；无法达成时说明失败项、证据和待决策事项，暂停依赖该门槛的合并。已通过检查仅在新变更或未解决风险需要时重复。

## 文档、交付与证据

改动应更新其归属文档：接口字段与任务契约在 interface，持久化在 database，默认配置在 configuration-contract，后端职责在 p5-domain-boundaries，前端职责与组件约束在 development-contracts，运行步骤在 README/部署/脚本说明。长期规范记录当前契约；执行记录保存提交、命令与结果，避免把阶段历史写成当前验证结论。

交付报告区分已实现、隔离验证和目标环境验收，记录对应提交及验证范围。模拟 HTTP/WebSocket、临时 Redis、Celery eager 和构建通过各自证明其覆盖范围；真实抓取、下载、worker、数据库恢复和网关联调按[验证状态](../django_backend/doc/validation-status.md)执行。

本轮沿用用户已授权的工作流：在 `/tmp/nassav-agent-worktree` 的独立阶段分支提交，质量门槛通过后合并 `idle`，结束时保持该工作树干净且位于 `idle`；默认工作树由用户使用。后续任务遵循其明确授权，未获得提交授权时先询问。

## 持久任务与资产提交

新增下载、刮削及所属翻译以 TaskJob 为状态所有者；Celery 派发、Redis 租约/投影和 WebSocket 提示分别承担运输、互斥与刷新职责。恢复新建 attempt/generation；所有检查点、翻译和正式文件提交检查执行归属。暂停与终止以写入者退出证明收尾，清理状态独立于任务终态。不再跟踪只改变浏览器列表。

TaskAssets 用持久准备日志、目标发布 marker 和共享文件锁协调文件/DB 补偿；复制、网络、媒体校验与大文件哈希在短写入 fence 外执行。旧同步路径的副作用顺序与新受控提交分别维护，不能互相套用。续传能力和跨容器恢复有明确限制，扩展时须先补归属、崩溃、取消和部分成功回归。完整职责、限制和检查清单见[任务控制架构](../django_backend/doc/task-control-architecture.md)。
