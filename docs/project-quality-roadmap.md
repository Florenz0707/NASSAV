# 前后端项目质量改进开发进度计划

日期：2026-09-28。状态：**待实施**。本文将静态评估转为可分阶段交付的开发工作。阶段状态只表示本计划的进度，不代表已有刮削、下载、Compose 或 PostgreSQL 支持尚未实现。

## 目标与边界

目标是收紧应用访问边界，消除数据库与 worker 的配置和启动歧义，规范配置失败行为，修复前端开发环境的实时连接与测试入口，再逐步降低大模块的维护成本，并整理历史文件、文档和设计规范偏差。

范围包括根目录 Compose 和文档、django_backend 的配置/API/Channels/Celery，以及 vue_frontend 的 API/WebSocket/页面/测试。允许为阶段目标重构相关模块，但一次只处理明确的业务域。origin_project 保留为历史参考，不在其中进行功能开发。

本计划不执行 PostgreSQL 正式数据迁移、生产数据库切换、SSE 替换、Byparr 重新选型或推荐算法重写。数据库切换继续依照[独立迁移计划](../django_backend/doc/postgresql-migration-plan.md)；本文只处理模式识别、防误连和部署验证。隔离环境测试通过不等于生产切换获准。

已确认的基线：基础 [Compose](../compose.yaml) 默认 SQLite，PostgreSQL 使用[覆盖文件](../compose.postgres.yaml)连接外部服务；刮削、下载、默认任务由三个独立 worker 消费。前端已有刮削任务测试，后端已有数据库备份适配。本计划须保持这些能力。

## P0：基线和决策

**范围：**盘点当前部署和代码入口，建立测试环境；不改变运行配置或真实业务数据。

1. 分别记录本机开发、默认 Compose、PostgreSQL 覆盖三种模式下 API、三个 worker、Beat 的数据库引擎、库名/schema、Redis 地址、监听地址和队列。记录来源与时间；凭证只记录「已配置／缺失」，不写入文档。
2. 确定目标访问模型：仅本机、可信局域网，或经反向代理远程访问。推荐目标为单用户登录会话，敏感 API 与 WebSocket 共用身份边界。若决定保留匿名本机模式，明确环回绑定和禁止外部暴露，将未实施认证记为接受风险，不能记为已修复。
3. 在隔离数据库和临时资源目录建立回归样本：Cookie 读取/修改、设置修改、资源删除、推荐重置、资源添加/刷新、下载进度、WebSocket 连接/重连和数据库备份。不得对真实库执行删除或重置测试。
4. 列出后端视图、任务、资源服务和前端推荐页面、资源 store 的职责；定位过时的单 worker、SQLite-only 文档段落；检查历史可执行文件的构建与运行引用。

**验收门槛：**三种模式的预期配置矩阵完整，实际运行模式已核实；访问模型有结论；每个回归样本能在隔离环境运行，依赖外部服务而无法运行的样本标明「待验证」及目标环境。不能依据 .env 字面值推断容器最终配置。

## P1：API 和 WebSocket 访问边界

**范围：**[DRF 设置](../django_backend/django_project/settings.py)、业务 API、[任务 WebSocket](../django_backend/nassav/consumers.py)、ASGI/网关配置和前端会话状态。不改刮削、下载、推荐的业务结果。

1. 建立端点授权矩阵：公开、登录可读、登录可写、仅内部访问。至少覆盖 Cookie、用户设置、资源删除、推荐重置、任务状态和 WebSocket。单独规定健康探针。明确浏览器会话、CSRF、跨域与 WebSocket Origin；不把 ALLOWED_HOSTS 当成认证。
2. 按 P0 决定实施统一身份校验，前端处理登录、会话过期和授权失败。WebSocket 在加入全局任务组之前完成身份及来源校验，断开后不能继续收到事件。刮削任务签名状态令牌继续保护快照。
3. 更新本机、Compose 和代理部署说明。若暂时只选本机匿名方案，则固化环回绑定并拒绝或明确阻断非本机部署；外部访问能力保持未完成。
4. 按访问模型添加自动化测试：认证模式下，匿名读取 Cookie、修改设置、删除资源、重置推荐及读取敏感任务均被拒绝，合法用户可完成原操作；未认证或非法 Origin 的 WebSocket 握手失败，合法连接可收到预期事件。本机匿名模式下，验证环回端口不可从其他设备访问，且本机原有操作正常。测试使用假凭证，不记录真实 Cookie。

**验收门槛：**每个敏感端点有明确访问规则；所选模式的 HTTP、WebSocket 和合法操作回归全部通过；默认 Compose 仍只绑定环回地址。认证模式下，未授权请求不能读取 Cookie 或修改/删除业务数据。若明确只支持本机且未实施认证，须通过环回隔离验证并记录接受风险，才可标为「已完成」（范围限定本机）；对外访问仍为阻塞。

## P2：部署模式与任务启动

**范围：**根 [Compose](../compose.yaml)、[PostgreSQL 覆盖文件](../compose.postgres.yaml)、[环境样例](../.env.example)、开发命令与 README/部署说明。不导入数据，不移动资源目录，不切换生产库。

1. 明确唯一可操作的模式入口：SQLite 用基础 Compose；PostgreSQL 必须显式加载覆盖文件及密码 secret。消除「只改 .env 的 DB_ENGINE 就能切换容器数据库」的歧义，必要时在渲染或启动阶段拒绝矛盾设置。
2. 统一 API、scrape-worker、download-worker、default-worker、Beat 和一次性 migrate 的数据库配置来源。逐服务检查渲染后的引擎、主机、库名/schema；诊断输出不得包含密码。
3. 将根和后端 README 中的单 worker、systemd、tmux 示例改为三个队列的准确命令，优先使用现有 nassav-worker-\* 入口。说明 Beat 的 scheduler profile 和唯一实例约束；修订仍声称备份只包含 SQLite/WAL 的段落。
4. 用独立数据目录分别渲染并启动两种模式，核对 migrate → API/worker 启动顺序、各队列有消费者；验证 PostgreSQL 凭证或连接失败时不会隐式使用 SQLite。

**验收门槛：**两种模式的 Compose config --quiet 通过；所有后端服务连接同一预期数据库；错误配置不会连接到意外的 SQLite；scrape、download、default 测试任务分别被目标 worker 消费；文档不再留下误导性单 worker 或 SQLite-only 操作说明。PostgreSQL 模式测试只证明配置与行为，不代表正式切换完成。

## P3：配置契约与启动初始化

**范围：**[Django 设置加载](../django_backend/django_project/settings.py)、配置模板、应用启动与日志初始化；保留有效配置的现有语义。

3. 盘点 AppConfig.ready() 的文件创建/异常吞掉和服务模块导入时的日志初始化。必要初始化应可观测、幂等、可测试；管理命令、ASGI 和 worker 多进程启动不得重复添加日志输出或悄悄跳过信号注册。

**验收门槛：**有效本地及 Compose 配置行为不变；空 YAML、缺键、非法类型、无效数据库引擎、无效凭证文件均有失败用例；错误不泄露秘密；manage.py check、ASGI 和 worker 对同一错误给出一致原因；多进程日志和信号行为有验证记录。

## P5：按业务边界拆分大模块

**范围：**先处理[后端视图](../django_backend/nassav/views.py)、[任务](../django_backend/nassav/tasks.py)、[资源服务](../django_backend/nassav/resource_service.py)、[推荐页面](../vue_frontend/src/views/RecommendationsView.vue)与资源 store。一次只拆一个域，不按行数机械搬运。

1. 为目标域画出 API → 应用编排 → 抓取/下载适配器 → ORM/文件持久化的调用路径，标出输入、输出、异常和副作用。先确认现有 ResourceService、任务状态、前端 API/store 的职责，避免复制第二套业务流程。
2. 依资源、下载、推荐等域逐步拆分：视图负责校验与响应映射；任务负责调度和重试；应用服务编排业务；持久化和外部访问归相应模块。保留 URL、响应 envelope、数据库 schema、Celery 任务名和消息字段，除非另立兼容迁移项。
3. 将前端推荐页面的数据获取/变更移至 API/store，可复用展示块抽为组件。资源 store 的网络请求、任务状态合并、UI 提示分清职责；保留轮询与 WebSocket 忽略旧版本的行为。
4. 每个业务域独立提交和验收：先固定关键行为测试，再搬移代码，运行针对性回归；更新模块说明后再拆下一个域。

**验收门槛：**入口 URL、响应结构、任务名、数据库 migration、资源路径与用户流程不变；新边界有行为测试支撑，文件变小本身不算完成；资源添加/刷新、下载进度、推荐反馈和页面刷新后的状态均通过。确需改契约时另列迁移说明与前后端联调验收。
