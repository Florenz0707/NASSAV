# Byparr 会话复用 P3 验证记录

P3 把 `direct_first` 直连 403/挑战后的共享会话刷新与旧 `POST /api/source/cookie` 自动获取入口接到同一 Redis 租约。锁键由规范化源、目标主机和代理路线摘要组成；锁内不保存 Cookie、UA 或代理凭据。`browser_first` 正常页面请求不等待该锁，人工设置/清除也不等待。

## 协调行为

- Redis 使用 `SET NX EX`、随机 owner 和仅持有者可续租/释放的 Lua 操作。60 秒 Byparr 预算对应至少 90 秒租期；超时提高时按控制请求、3 秒探测和收尾余量提高租期。后台线程续租；失去所有权后禁止写入共享会话。
- 持锁者在浏览器前重读数据库版本；若已有可用新会话，只对目标页面重试一次直连。等待者有限退避并读共享版本，拿到新会话后只重试一次直连。Redis 不可用、owner 崩溃、锁过期或刷新失败时，本次页面仍可取独立浏览器页，但不写共享会话。
- 直连探测证明候选 Cookie+UA 不可复用后，按站点和路线短暂记录不可复用；其它详情页仍分别向 Byparr 获取页面。旧自动 Cookie 路径用网络前版本与租约守卫做 CAS，人工更新不会被晚到结果覆盖。

## 离线验收

`tests/test_session_coordination.py` 覆盖 10 个同站并发 403 请求只触发一次可复用浏览器刷新、不同站点无互锁、租约过期旧 owner 禁写、崩溃/超时、Redis 断连、人工更新竞争、不可复用时不同页面各自浏览器获取，以及 MissAV/Jable 旧自动 Cookie API。SQLite 后端全量测试为 `387 passed, 13 skipped`；隔离 PostgreSQL 的 P3/P2/P1 专项测试为 `43 passed`。真实 Redis 的 Lua 所有权、续租、结果通知和短期不可复用标记使用独立 Redis 7 容器验证。测试不连接生产 Redis 或写生产数据库。

P4 的配置开关、管理界面与观测仍未实现；两源继续保持 `browser_first`，实际提速需在 P5 灰度验收。
