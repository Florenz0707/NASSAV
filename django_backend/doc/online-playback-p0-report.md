# 在线播放 P0：真实来源与传输探测

日期：2026-10-10。代码基线：`30c8598`。关联[设计与执行计划](online-playback-design.md)、[脱敏原始测量](online-playback-p0-evidence.json)。本轮只进行探测和文档更新，没有接入正式播放器、修改依赖、迁移数据库或发布播放接口。

## 结论与准入范围

**两个真实来源样本通过同源探针完成解码、首帧、跳转、暂停和关闭，可推进 P1 的会话与播放描述。**现有 curl_cffi 异步 stream 不满足慢消费者的内存和中止要求，不能直接作为 P2 默认媒体转发；HTTPX 0.28.1 在隔离环境完成了替代传输验证，可作为 P2 候选。P2 仍须完成真正 ASGI 响应、客户端断连、多路慢消费者、容量及安全检查，不能把这个同步探针当作生产网关。

实际验证范围为 Linux Google Chrome 152＋hls.js 1.6.16、H.264/AAC、TS VOD，涵盖无加密和 AES-128。没有验收 Safari/iOS、Firefox、Android、fMP4、直播、DRM、多画质切换、完整两小时播放或签名到期后的无缝恢复。现阶段只承诺这两个样本的短时实测，不扩大到所有资源和来源。

## 隔离与方法

- 运行实例为 Django 6.0、curl_cffi 0.14.0、PostgreSQL；全局来源代理启用，下载代理未配置。Jable 配置 browser_first，MissAV 配置 direct_first；BrowserFetch 使用 Byparr，公共 ProxyServer 容量为 2，会话复用关闭。
- 只读选择库中 Jable 的 SONE-411、MissAV 的 ADN-495。绕过 AVResource 中的 m3u8、持久播放事实缓存及旧详情缓存，直接使用独立来源实例的 get_html/parse_html 重新获取。未调用添加、刷新、下载或推荐业务入口。
- 获取进程设置 PostgreSQL `default_transaction_read_only = on`；CookieRepository 替身只读已有 Cookie 行，新增会话只保存在进程内。页面浏览器仍通过 create_page_fetch_service/ProxyServer 使用生产共享容量；不直接调用 Byparr 绕过限流。
- 新链接、Referer、UA 与代理凭据只存在权限受限的临时文件。媒体请求使用全局来源代理，将容器内 host.docker.internal 等价映射为宿主机 loopback 代理入口；显式禁止环境代理/NO_PROXY 改写路线。直连是独立对照实验，不是默认回退。
- 临时网关仅绑定 127.0.0.1，按固定样本注册资源 URI，重写清单中的分片/密钥引用。每次上游最多 12 MiB，总量最多 96 MiB、请求数最多 60；字节只暂存内存，不写 resource、.tasks 或完整视频文件。
- Playwright 驱动已安装 Google Chrome，真实加载源媒体并检查解码帧数；无截图、录屏或页面预览图。探针使用同步有界缓冲，仅回答媒体是否能解码，不证明异步服务端背压或正式会话控制。

首帧指标为开始加载到 currentTime 超过 0.5 秒且已解码视频帧，并非精确的第一帧渲染时间。它不包含此前的来源准备时间。首段范围请求只读取少量媒体，浏览器两轮短时播放合计转发约 14 MB。

## 新来源地址与媒体特征

| 项目         | Jable / SONE-411                        | MissAV / ADN-495                                                               |
| ------------ | --------------------------------------- | ------------------------------------------------------------------------------ |
| 重新获取耗时 | 41.36 秒，浏览器调用 1 次               | 63.15 秒，浏览器调用 1 次                                                      |
| 根/媒体清单  | 200，有效媒体清单                       | 主清单/媒体清单均 200                                                          |
| 清单结构     | 1817 个分片，VOD 7268.43 秒             | 3 个画质，选择现有最高档 1280×720 / 标称 2.8 Mbps；1802 个分片，VOD 7206.50 秒 |
| 媒体格式     | TS、H.264 avc1.640020、AAC mp4a.40.2    | TS、H.264 avc1.4d401f、AAC mp4a.40.2                                           |
| 加密与初始化 | AES-128，密钥 200/16 字节；无 EXT-X-MAP | 无加密；无 EXT-X-MAP                                                           |
| 首段 Range   | 206，Content-Range 与 65536 字节一致    | 206，Content-Range 与 65536 字节一致                                           |
| 媒体 Cookie  | 不携带，仍可获取分片和密钥              | 不携带，仍可获取分片                                                           |

实际 MissAV 分片响应 Content-Type 为 image/jpeg，但字节具有 TS 同步结构，浏览器成功解码；Jable 密钥的 Content-Type 为 video/mp2t，实际只有 16 字节。网关不能只以 MIME 判断成功，也不能把 text/html 错误页按媒体放行。加密 TS 在解密前没有明文同步字节，校验须区分加密、密钥和普通 TS。

上述码率只是主清单 BANDWIDTH 标称值；没有完整采样 Jable 码率、媒体平均码率或持续播放流量。正式容量需要 P2/P5 再测量。

## 请求上下文、跨域与出口

1. 保留实际详情页 Referer、固定 UA，经全局来源代理请求：两者首段均 206。
2. 同一代理，删除 Referer：Jable 本次首段仍 206；MissAV 返回 403/HTML。因此 MissAV 的 403 不可一律解释为链接过期。Jable 单个首段允许省略不能推出所有清单、密钥和后续资源均不需要 Referer。
3. 带 Referer 的显式直连对照：本次两个首段也能读取。不能据此自动关闭代理、忽略来源准备路线或断言所有来源不绑定 IP。
4. Chrome 经同一代理从 loopback 页面直接 fetch 新媒体清单：两者均出现 CORS policy 错误，JavaScript 无法读取。原始清单/分片响应也没有 Access-Control-Allow-Origin。正式默认采用同源网关。
5. 公共 IP 回显实验中，ProxyServer 包装的浏览器路径与 curl 媒体路径的出口 IP 相同。只保留一致性结果，不记录真实 IP；这是该回显目标的出口证据，没有取得 CDN 服务端日志，不能证明代理对所有域名的路由都一致。

媒体请求没有携带源站 Cookie，说明本次媒体链路不需要 Cookie；页面抓取仍可能使用已有/浏览器 Cookie。UA 切换和无效 Range 的补测结果见脱敏测量。跨域结果不能用 no-cors 解决，因为 opaque 响应不能提供给 hls.js 解析。

## 浏览器播放验收

本机 Playwright Chromium 136 对 H.264/AAC 的 MediaSource 能力检测均为 false，不能用它判定真实来源失败。改用 Google Chrome 152 后检测为 true，实际通过 hls.js 播放。虽然该 Chrome 的原生 HLS 检测返回 maybe，本轮强制走 hls.js，没有将其视为原生路径验收。

| 验收项                    | Jable            | MissAV           |
| ------------------------- | ---------------- | ---------------- |
| 第一次/第二次首帧指标     | 4.977 / 4.195 秒 | 1.840 / 1.877 秒 |
| 第二轮已解码视频帧        | 36 帧            | 21 帧            |
| 第二轮跳转目标            | 3634 秒          | 3603 秒          |
| 跳转到继续推进的用时      | 4.776 秒         | 1.843 秒         |
| 暂停 1.5 秒后播放位置变化 | 0 秒             | 0 秒             |
| 关闭并等待后网关在途请求  | 0                | 0                |

第一轮 Jable 出现可恢复的 bufferSeekOverHole/bufferStalledError，仍成功跳转；第二轮无该事件。正式播放器需处理缓冲/跳转，不把每个非 fatal 事件展示成播放失败。关闭验收是销毁播放器、停止加载及拒绝后续样本请求；不是尚未实现的 DB 会话撤销，也不证明同步探针能即时中止在途上游连接。

## 异步传输与缓存有效期

使用本地 loopback fixture 按 256 KiB/40 ms 发送总共 16 MiB，消费者取一块后停读 1 秒，测量 Python 队列/内存与关闭耗时；固定版本，两个库分别测试，不修改项目依赖。

| 测量             | curl_cffi 0.14.0                                    | HTTPX 0.28.1                                   |
| ---------------- | --------------------------------------------------- | ---------------------------------------------- |
| 停读后的缓冲证据 | asyncio.Queue maxsize=0，417 个 chunk、6537672 字节 | 按需 aiter_raw(16384)；没有库级全量 chunk 队列 |
| Python 分配峰值  | 6623445 字节                                        | 500062 字节                                    |
| aclose 用时      | 1.549 秒，等待剩余传输                              | 0.0015 秒                                      |
| 关闭后积压       | 16761288 字节，接近完整响应                         | 未读取剩余响应便关闭                           |

Python 峰值包含同进程 fixture 分配，不是 RSS，也不包含内核/TLS 缓冲；不能直接换算线上并发内存上限。curl_cffi 额外实验先设置 quit_now 再关闭可快速停止，仍未解决生产级有界背压；不能把其内部事件当公共稳定接口直接使用。项目当前版本的 session.py/utils.py/models.py 可核对无界 Queue、put_nowait 和 aclose 等实现。

HTTPX 通过同一全局 HTTP 代理实际读取两个来源的清单、Range 分片、Jable 密钥，证明这些样本的 CDN 不要求 curl 浏览器 TLS 模拟。建议准备阶段保留现有来源/PageFetchService，媒体 PlaybackTransport 评估独立 HTTPX Adapter；其他来源、SOCKS、超时/取消和 TLS 特征仍在 P2 覆盖。[异步流官方契约](https://www.python-httpx.org/async/)、[代理官方契约](https://www.python-httpx.org/advanced/proxies/)。

HTTPX 复测发生在获取批次开始后约 403/406 秒，两个清单仍为 200、分片为 206、密钥有效；链接在初次获取后约 6/5 分钟仍可访问。地址没有可直接解析的过期 query 参数，不能推断固定有效期或无限有效。5 分钟缓存 TTL 仍是重新解析策略，真实过期、一次刷新与媒体身份校验留给 P4/P5；本轮不为等待链接失效持续下载视频。

## 后续实施约束与收尾

- P1 保存完整播放描述及版本/执行归属，明确来源准备可能耗时 40–60 秒，HTTP 创建接口不能同步等抓取结束。
- P2 采用独立可替换媒体传输，先验证有界内存和断连清理；保留实际 Referer、目标作用域及代理路线。不能直接上线当前同步探针或现有 curl 异步流。
- P2 对 AES-128 密钥、错误 MIME、206/416、清单依赖和 HTML 错误页补充回归；fMP4/init 首先使用本地合成 fixture，不能宣称已由这两个真实来源覆盖。
- P3 保留编码能力检测与具体失败提示，P5 使用真实浏览器/设备验收；无专有解码器的自动化 Chromium 不作为唯一浏览器标准。
- 本轮只在独立 P0 分支更新设计和测量记录；正式配置、生产表、资源目录与用户默认 worktree 不变。临时服务器、浏览器及包含播放地址的目录在结束时清理。文档变更执行链接检查和 pre-commit，不以其通过替代来源实测。

P0 结果允许继续设计中的 P1；现有 curl_cffi 默认异步流不通过媒体转发选型门槛，必须按上述候选/抽象调整后才进入 P2 实现。此报告不表示正式系统已经支持在线播放。
