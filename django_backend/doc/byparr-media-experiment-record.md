# Byparr 第三步：blockMedia 与等待耗时实验

日期：2026-10-01。对应[替代方案调研第三步](byparr-alternative-approaches-research.md)。逐项脱敏数据见 [JSONL 证据](byparr-media-experiment-evidence.jsonl)。本次是固定版本隔离实验；正式 Byparr、配置、Cookie、Redis 与任务不参与写入。

## 环境和可重复方法

- 镜像固定为 `ghcr.io/thephaseless/byparr@sha256:874f719518f617d03a60e03411fc5d090647e1a877041e81f8dc965927c7deb6`；隔离 `/ready` 报告 `3.0.4`，使用与正式服务同样的 Docker 网络、host-gateway 映射和 512 MiB 共享内存。未开放宿主机端口。正式与隔离容器的 utils.py、endpoints.py、challenge.py、models.py 四个核心源码 SHA-256 逐项一致。固定代理路线不等同目标站看到的公网 IP 永久不变。
- [计时包装器](../scripts/byparr/instrument_media_experiment.py) 调用镜像原有 `get_browser()`、`read_item()`、挑战求解和路由安装。默认 networkidle 模式仅包装异步方法记录耗时、统计资源类型与 `Route.abort()` 次数；不调整浏览器指纹、代理、导航/挑战/等待逻辑或默认超时。业务等待候选模式的调整见下节。返回结果添加实验专用 `experimentTimings`，正式应用没有增加该字段。
- [只读探针](../scripts/probe_byparr_media.py) 在 API 容器中读取代理配置，使用现有 `ByparrPageClient` 和 `PageFetchService.validate_result`；在控制请求中显式发送 `blockMedia=false/true`。同一番号、同一配置代理路线配对，奇偶番号反转顺序，工具支持第二时段再反转；每次仍新建浏览器，没有浏览器会话复用或业务 HTML 缓存。HTTP 控制连接复用对两种参数一致。
- Jable 从当前 `/latest-updates/` 发现详情；MissAV 从首页发现番号后使用已验证的 `/cn/{avid}`。Jable 必须有播放地址且标题匹配请求番号，MissAV 必须有视频 UUID 且标题匹配番号。另测试不存在详情，不能以提供方 HTTP 200 放行。若执行第二窗口则重用首窗口清单；本轮媒体参数首窗口未显示稳定收益，因此停止扩展该参数。等待 PoC 另在稍后时段使用相同番号的子集重新做配对，并保持两臂 blockMedia=false。
- 若默认参数有效而阻止媒体后页面无效，探针立即停止，不继续推广参数。统计包含全部已发请求，失败和慢请求均纳入 P50/P95，不用丢弃失败后的子集制造提速。P95 使用 nearest-rank。

## 分段含义与限制

`browser_startup_ms` 包含 InvisiblePlaywright 上下文进入阶段（含其内部启动与环境准备），不是纯浏览器进程 spawn；`context_ms`、`page_ms` 分别为新 context/page。`navigation_ms` 是原有 `page.goto()`，保持其默认 load 等待语义；`domcontentloaded_ms` 为其后显式等待。`challenge_detection_ms` 是首次挑战检测，`challenge_solving_ms` 包含原有循环、点击和 settle 时间；`networkidle_ms` 是原有页面闲置等待，超时另标记。`content_ms` 是最终内容构建，Cookie 提取及 JSON 编码等剩余工作不强行归入某一阶段。`browser_cleanup_ms` 为浏览器依赖退出阶段，隔离端点在关闭浏览器后才返回，`server_total_ms` 包含该清理。客户端记录控制往返和业务校验耗时。阶段中位数不要求相加等于总中位数。

包装器没有使用原 `main.py` 的 gzip 与访问日志中间件；两参数共用同一包装器，适合比较参数和内部阶段，绝对控制往返时间不能直接等同正式 API 延迟。事件监听、计时和资源统计也有开销，结果只用于隔离方案评估。不能从资源请求次数推断传输字节，因为中止资源可能重试。

## 结果与下一步判定

### blockMedia：本窗口不支持启用

第一窗口：北京时间 10:52–11:17。

| 来源   | 默认有效率 | 阻止媒体有效率 | 默认 P50 / P95     | 阻止媒体 P50 / P95 | 配对节省中位数 | 阻止媒体更快的配对 |
| ------ | ---------: | -------------: | ------------------ | ------------------ | -------------: | -----------------: |
| Jable  |      20/20 |          20/20 | 21.922 / 35.386 秒 | 20.621 / 40.021 秒 |       0.886 秒 |              12/20 |
| MissAV |      20/20 |          20/20 | 10.004 / 11.189 秒 | 9.930 / 14.023 秒  |       0.303 秒 |              11/20 |

两站的不存在详情在两种参数下均被拒绝，共 0/4 误接纳。阻止媒体有实际生效（Jable 中位中止 104 个资源，MissAV 为 99.5 个），但对两站 P95 都未改善；不能据中位数小幅降低就启用。资源计数不能证明重试的原因。没有发生已验证默认页被阻止媒体破坏的情况，因此未触发业务失效停止条件；停止继续扩大参数实验的原因是缺少稳定时延收益。本轮不进行第二窗口参数放行，也不部署配置。

| 来源/参数       | 启动中位数 | 导航中位数 | 挑战求解中位数 | networkidle 中位数 |
| --------------- | ---------: | ---------: | -------------: | -----------------: |
| Jable 默认      |   2.131 秒 |   0.664 秒 |      10.415 秒 |           7.257 秒 |
| Jable 阻止媒体  |   2.118 秒 |   0.663 秒 |      10.423 秒 |           5.803 秒 |
| MissAV 默认     |   2.136 秒 |   5.526 秒 |           0 秒 |           0.769 秒 |
| MissAV 阻止媒体 |   2.128 秒 |   5.399 秒 |           0 秒 |           0.880 秒 |

按全部服务器计时加总，Jable 默认的挑战和 networkidle 分别占 42.3%/41.1%，20/20 请求检测到挑战；MissAV 默认的导航占 55.4%、启动占 21.7%、networkidle 占 9.5%，本窗口 0/20 检测到挑战。未发生 networkidle 等待超时，慢请求是等待自然结束，不是超时兜底造成。Jable 默认最慢请求为 50.153 秒、阻止媒体最慢为 49.766 秒；已观察到一个后者样本单独闲置等待 35.094 秒，因此尾部瓶颈明确。MissAV 当前证据不支持仅替换 networkidle 来解决主要耗时。

### Jable 业务就绪等待 PoC

仅在隔离候选实例显式设置 BYPARR_EXPERIMENT_WAIT=business。两臂媒体参数均关闭，使用相同镜像和包装器。候选保留原导航、DOM 等待、挑战求解及其 settle；只在原 networkidle 阶段轮询页面 HTML，要求同站点、精确番号标题、播放地址和封面结构，再构建新的 HTML 快照。探针另调用真实 Jable.parse_html() 校验播放地址、番号、标题与封面；不会在挑战求解期间运行额外页面 JavaScript。未识别的站点及列表路径继续原 networkidle。代码与反向契约见[业务内容判定](../scripts/byparr/business_ready.py)。

PoC 在北京时间 11:19–11:26 使用首窗口前 10 个不同番号，单独交错测量；JSONL 的 W2 标签表示该 PoC 时段，不表示完成 blockMedia 的第二窗口。两种策略均 10/10 通过实际解析。默认 P50/P95 为 21.469/25.394 秒，业务就绪等待为 14.741/21.479 秒；9/10 配对更快，配对节省中位数 6.985 秒。对照 networkidle 中位数为 7.341 秒，候选的业务等待中位数仅 7.450 毫秒；挑战求解中位数仍为 10.427/10.413 秒，表明本次节省来自挑战后的等待。候选首条浏览器启动为 9.112 秒，而其他启动通常约 2 秒；该冷启动样本完整保留在 P95 中，未作为异常值剔除。

不存在详情均未被误接纳，但初始 PoC 的失败耗时明显变差：默认 16.053 秒得到 page_mismatch，候选 63.326 秒得到 timeout，其中业务标记等待 48.093 秒。原因是只等业务标记会在不存在页面上用尽原 60 秒预算（浏览器启动/清理额外计入）。因此该 PoC **尚不支持正式部署**；后续实现需为快速业务检查设短上限，标记未齐全时回到原等待或使用可靠的不存在页判定，同时仍由页面服务拒绝错页。不应延长总预算，也不能提前返回未通过校验的 HTML。保留初始实验代码以复现这一缺陷，不把它包装成已放行优化。

本次已完成第三步的公开参数 A/B、阶段分解，以及由等待尾部瓶颈触发的最小 PoC。结论是 blockMedia 维持默认关闭；Jable 业务就绪等待值得后续完善有界回退并复测；MissAV 应先把 goto 的主响应与 load 阶段再拆分，当前 networkidle 不是其主要耗时。进入正式方案前仍须两个独立时段各至少 20 页、反向样本、API/worker 及媒体下载验收；本次没有完成这些放行门槛。

## 离线验证和收尾

完整后端隔离测试为 405 passed、13 skipped。新增探针契约覆盖参数的单变量变化、平衡顺序、计时不串请求、失败请求计入 P95，以及业务结构缺失、错番号、挑战和未知站点。实验的两个临时 Byparr 容器、API 容器内探针目录及宿主临时结果均已清理，脱敏原始证据保存在本文链接的 JSONL 中。
