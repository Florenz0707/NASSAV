# 多用户扩展路线与数据边界

状态：个人播放进度及第二阶段收藏、已观看、备注、通用设置已实现，尚未开放多用户业务访问。当前 `is_operator` 只允许配置指定的启用账号；已有 PlaybackSession.user 不代表整个资源库已经支持多用户。个人进度实现状态见[播放进度架构](playback-progress-architecture.md)，本轮状态与迁移见[个人状态与设置](personal-state-architecture.md)。

## 共享事实与个人状态

共享：AVResource 原站元数据、演员/类别、正式封面/视频、提供者事实缓存、代理并发容量。缓存仍不得包含用户偏好，删除共享视频影响所有用户。

个人：播放进度、收藏、已观看、备注、通用设置、观看历史、推荐偏好、反馈、黑名单与播放列表。禁止只移除用户名判断而保留共享状态写入口。

| 能力              | 建议模型或边界                                                                    | 优先级           |
| ----------------- | --------------------------------------------------------------------------------- | ---------------- |
| 继续观看          | PlaybackProgress 按 user 查询；资源存在及访问权限重新核验                         | 第一阶段         |
| 收藏/已观看/备注  | UserResourceState，唯一(user, resource)；资源删除级联，无评分                     | 第二阶段已实现   |
| 通用设置          | UserPreferences，唯一user；JSON覆盖值、created_at/updated_at，旧INI显式导入缺失行 | 第二阶段已实现   |
| 观看历史          | 与最新位置分开，采用有界 PlaybackHistory/事件记录及保留策略                       | 后续可选         |
| 推荐与黑名单      | 用户拥有推荐状态、job、历史、反馈、偏好；generation/fence 加 user 域              | 第三阶段         |
| 播放设置          | UserPlaybackPreferences：音量、倍速、字幕和默认模式；设备差异可另存本地           | 第三阶段         |
| 稍后观看/播放列表 | 用户拥有列表和有序条目；是否共享单独授权                                          | 第四阶段         |
| 跨设备接续        | 复用个人进度，服务器决定写入归属；推送只作提示                                    | 第四阶段         |
| 角色/配额         | 管理员拥有账号、删除正式资产、全库维护；普通用户仅允许授权动作                    | 开放多用户前必需 |

## 权限与迁移

先定义共享资源库还是用户私有库；首选共享事实库加个人状态。若需要私有库，新增资源可见性/授权关系，不能仅靠过滤前端列表。

保留登录/CSRF/同源媒体鉴权，将 is_operator 拆为启用用户准入与管理员权限。HTTP、WebSocket、任务快照、媒体请求、缓存投影均应用一致的用户授权；猜测 UUID 不构成权限。

TaskJob 当前任务/资产语义必须逐项审计后明确提交者、可见性和控制者。下载及刮削影响共享文件，重复任务仍使用共享锁，普通用户不能取消他人的执行或删除共享资源。系统维护 job 可由管理员查看。

AVResource.watched/is_favorite 现仅保留旧共享快照；第二阶段通过import_personal_data只向明确指定的原操作者导入旧值，不复制给全部用户。运行时个人状态与六项通用设置由数据库按user持有，原INI不再读取。推荐状态、历史、黑名单和反馈同样先定义旧数据归属，再可逆迁移。共享抓取缓存继续复用，但结果按当前用户重做库存/偏好/权限判断。

播放容量同时保留全局与每用户限制，默认播放会话上限已有按 user 的基础。账号停用、退出登录或删除应撤销所属会话；同时核查在途媒体与任务控制，不能只停止前端轮询。

## 执行顺序与门槛

1. 个人播放进度，暂不开放多用户登录。
2. 明确权限矩阵，覆盖用户间不可见/不可写、管理员操作及 WebSocket/媒体访问。
3. 个人资源状态与通用设置、旧共享值/INI归属迁移（本轮已实现）；观看历史单列为后续可选能力。
4. 推荐链路全面用户隔离：取消/重置后的旧执行不得写入；共享代理容量不变。
5. 播放列表、播放设置、跨设备提示和配额。

每阶段独立分支、离线质量门槛与 SQLite/PostgreSQL 迁移检查，目标部署验收独立记录。首版不自动增加公开注册、邀请、共享链接或匿名播放。
