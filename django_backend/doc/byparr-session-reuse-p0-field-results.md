## 环境与出口

- 代码基线 `04ca7200bd532cbbb46a2895e0f099cc0384c164`；运行中 API 的 `Jable.py`、`MissAV.py`、`page_fetching/browser.py`、`page_fetching/service.py` 的 SHA-256 均与工作树一致。Compose 有 1 个 API、1 个 scrape worker（`-c 1`）、1 个默认 worker、1 个下载 worker；API 与 worker 之间仍可并发。
- Django 有效数据库为 PostgreSQL 16.15；MissAV/Jable 域名分别为 `missav.ai`/`jable.tv`，策略均为 `browser_first`。正式 Compose Byparr 容器镜像 digest 为 `sha256:874f719518f617d03a60e03411fc5d090647e1a877041e81f8dc965927c7deb6`；探测只连正式容器。
- Django 与 Byparr 都使用运行配置中的同一代理路线 `route-A`。两轮各 3 组 `api.ipify.org` 配对观测，直连与浏览器出口 **6/6 相同**，IP 值未记录。该证据覆盖探测目标及所测时间；代理若按目标域名或时间轮换，不能由这 6 组推断长期出口相同。
- 探测从 `nassav-api-1` 容器发出，不走资源缓存，不写 `SourceCookie`。现场前后 `SourceCookie` 均为 2 行，最新 `updated_at` 均为 `2026-04-11T15:15:41.863000+00:00`。Byparr 适配器只保留提供方 HTTP 状态，`solution.status` 未作为目标 HTTP 状态记录；页面由最终域名、挑战与业务结构判定。证据不含 Cookie 值、完整 UA、代理凭据或公网 IP。

## 反向样本与会话时效

- Jable 不存在详情和把真实列表交给详情校验时，Byparr 提供方均报 HTTP 200，但业务结构均为 `invalid_structure`；未将浏览器 Cookie 当作有效候选。Jable 已知有效详情的无 Cookie 直连返回 HTTP 403 且被识别为挑战，表明不能用状态码或 Cookie 存在单独判定页面有效。
- 单独从 Jable `LULU-450` 获取一组会话并只保存在进程内存，立即、约 5 分钟、约 10 分钟分别对同页及 `LULU-449` 直连。逐次有效性见下方会话时效表。某次失败无法单独证明 Cookie 到期，也可能是站点或代理行为波动。

## 同一会话的时效观察

额外取得一组 Jable `LULU-450` 浏览器 Cookie+UA，仅保存在单个探测进程内存，分别用原样会话访问同页和 `LULU-449`。这里的年龄取单调时钟，数据见证据 JSONL。

|   会话年龄 | `LULU-450` 同页 | `LULU-449` 跨页 |
| ---------: | --------------- | --------------- |
|    约 1 秒 | 403 挑战        | 200，有效       |
|  约 5 分钟 | 403 挑战        | 403 挑战        |
| 约 10 分钟 | 403 挑战        | 200，有效       |

跨页在第 5 分钟失败、第 10 分钟恢复，因此不能从单次 403 推断 Cookie 已过期；同页持续失败也说明会话可用性具有页面差异。本次只能证明该会话在取得后约 10 分钟仍有一次有效跨页请求，不能给出稳定有效期下界。

## P0 判定

**Jable 的 P0 最低证据门槛已达到**：两个时段均有配套 Cookie+UA 同页及跨有效详情页成功，四组对照清楚区分 Cookie 与 UA 的共同作用；两轮出口配对一致。**保持 `browser_first`，不启用 `direct_first`**：主样本直连只有 6/12 有效，详情跨页仅 3/6 有效，与后续灰度要求的至少 95% 有效页率相距很远；两时段各只有 6 页，不能替代 P5 每时段至少 20 请求及 24 小时观察。P1 可使用 Jable 作为会话数据与回退机制的受控实现对象，不能据本次 P0 直接切策略。

**MissAV 不放行策略切换**：当前三个详情的业务结构与直连均有效，但无 Cookie 同样有效，复用效果没有独立证据；现有挑战判定还会误拒正常业务页。保持 `browser_first`，先修正并离线/在线回归该判定，再单独评估直连优先是否有价值。
